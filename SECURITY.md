# Security Policy

## Supported versions

Security fixes are provided for the latest stable release line and the current
development line. Older releases may not receive fixes.

## Reporting a vulnerability

Please do not open a public issue for a suspected security problem.

Use one of these paths instead:

1. If this repository has GitHub Security Advisories enabled, submit the report
   through the private advisory flow.
2. Otherwise, open a private report to the maintainers through the contact
   channel listed in the repository metadata or project docs.

Include:

- a short description of the issue
- the affected version or branch
- the impact you observed
- steps to reproduce
- any proof of concept or logs that help explain the problem

## Encrypted reports

No project-specific PGP key is published in this repository right now.

If a maintainer PGP key is added later, encrypt the report to the published
public key and include the fingerprint in your message. Until then, use the
private advisory or maintainer contact path above.

## Response process

We aim to acknowledge reports promptly, triage them, and work with the reporter
to confirm impact, reproduce the issue, and coordinate a fix and disclosure
timeline.
