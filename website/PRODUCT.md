# Product

## Register

brand

## Users

Developers and technical decision-makers evaluating Spinosa. Developers land on the page seeking a CLI tool to install — they want clarity, speed, and zero friction. Decision-makers (CTOs, tech leads) assess credibility, polish, and alignment with their stack. Both groups share a low-tolerance for marketing fluff and generic startup aesthetics.

## Product Purpose

A one-page landing that distributes the Spinosa CLI tool. The page exists to communicate what Spinosa is (through imagery and tone, not copy), and funnel visitors into a single action: copying the install command. Success is measured by install rate, not scroll depth or time on page.

## Brand Personality

Sharp, minimal, confident. Italian-Mediterranean roots worn lightly — the warmth is in the imagery and accent, not in surface decoration. Communicates through restraint: one command, one background, one brand mark. No feature lists, no testimonials, no hero metrics. The confidence comes from what's left out.

## Anti-references

- Generic SaaS landing pages: hero metrics, gradient CTAs, testimonial rows, pricing tables, feature grids.
- Editorial-magazine aesthetic: italic display serifs, rule-separated columns, lowercase metadata, no imagery.
- Cookie-cutter dev-tool pages: neon terminal aesthetics, monospace-everything, dark-mode-as-default, abstract geometric hero illustrations.
- The hero-metric template (big number + small label + gradient accent).
- Tiny uppercase tracked labels above every section ("ABOUT" "PROCESS" "PRICING").

## Design Principles

1. **One action, one page.** The only interaction is copying the install command. Everything serves that flow. No secondary CTAs, no navigation, no scroll targets.

2. **Imagery carries the brand.** The Mediterranean coastal image IS the personality — sun-cured, warm, grounded. Color, typography, and layout exist to frame it, not compete.

3. **Restraint as confidence.** What's left out communicates more than what's included. No gradient text, no glass, no side-stripe borders, no card decks. Every visual element earns its place by necessity.

4. **Developer-native polish.** Respects developer taste: crisp typography, proper spacing, responsive without breakpoint hacking, accessible by default. The page must work as well on a terminal-browser as on an iPad.

5. **Accessibility is not optional.** WCAG AAA contrast on all text. Keyboard-navigable copy button with visible focus rings. Reduced motion respected. The page's minimalism must not come at the cost of exclusion.

## Accessibility & Inclusion

WCAG AAA target. Text contrast ≥7:1 against background. Copy button is fully keyboard accessible with visible `:focus-visible` ring. Reduced motion: all animations disable under `prefers-reduced-motion: reduce`. The single-page layout with no scroll requirement means no motor-control-demanding interactions.
